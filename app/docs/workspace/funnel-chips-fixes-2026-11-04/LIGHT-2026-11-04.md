## The four bugs, their wire-verified root causes, and the fixes

1. **No text above the shelves.** Captured the live SSE
   (`repro-wedding-sets-stream.txt`): the model wrote exactly two sentences,
   "I'll search our wedding ring sets for you." and "Now I'll curate the best
   options and display them." — both narration-class, both dropped by the
   sentence filter. `messageCarriesText` tested the RAW text, concluded the
   message had a voice, and suppressed the tool's own intro ("Beautiful wedding
   sets to celebrate your love…") as a second voice. Filter ate everything; the
   fallback never armed. Fix: `messageCarriesText` now tests `displayText()`
   output — "carries text" means text that renders. A narration-only message
   reads as silence and the intro stands in.

2. **Applied value re-offered (White after White).** Captured the refine
   response (`repro-refine-white-response.json`): the applied exclusion was
   exact-attribute only, and the index models one physical facet under sibling
   attributes. `Catalog_JewelryMaterialNavigationColor:White` was excluded;
   `Catalog_MaterialInformation.MaterialColor` (subset value-set) re-offered
   White/Yellow/Rose. Fix: union-find over returned attributes — value sets
   where either is a subset of the other, or Jaccard >= 0.5, are ONE axis;
   the applied value excludes across the whole class. Index-derived, no
   attribute whitelist (2026-10-23 law respected).

3. **Second screen looks like a different screen.** The refined view renders a
   flat grid — a client search has no curated group titles, and inventing
   families is banned. Chrome order now matches the unfiltered shelf (tiles,
   then Narrow it down, Back to all last). The structural difference (no group
   headings on a refined shelf) is inherent to the client refine; options for
   Arijit: regroup refined hits under the ORIGINAL agent group titles by
   objectID, or accept the flat shelf.

4. **"14K" twice, "Lab Created" twice, "950", "Sterling", no labels.** Same
   sibling-attribute root cause as #2 (purity exists three times; creation
   classification twice). Fixed by the class merge in #2. Rows now carry
   mechanically derived labels (strip family prefix + Navigation/Information
   tokens, split camel case, dedupe repeated words). Two value labels are
   display-only maps cross-checked against the same response: `950` ->
   "Platinum 950" (the four 950 records are exactly the four Platinum Over
   records), `Sterling` -> "Sterling silver" (28 = 28 Silver).
