Examples and walkthrough

One real turn, captured from the production storefront, stepped through stage by stage: what the shopper sent, what the agent built, what the tool verified, and why the reply reads the way it does. Then the chip refinement that followed it, and the failure scenarios the prompts teach.

The turn: "Show me opal earrings" #

The shopper typed five words. Here is the whole turn, with what happened at each stage and which rule produced it.

StageWhat happenedWhich rule
1. SendThe browser posts the message with the turn's session state: accepted facts and the chip selections live on screen (none yet, first turn).Session state rides in turn metadata; the agent reads it as state, not evidence.
2. SearchThe agent builds one search: query "opal earrings", no facet filters, because the shopper named a stone but no metal. The platform executes it against the in-stock product index and streams hits plus facet counts.One search per turn; named stones ride as facet filters when a vocabulary value matches the words.
3. PickThe agent chooses 12 candidate pieces from the streamed result, best first, and picks the facets worth showing as chips (metal purity split this result meaningfully).The model curates; the search result alone never renders.
4. Verifypresent_products runs in the browser: requirement check (the shopper named no material, so none enforced), then per piece: exists, in stock, priced, photographed, no same-design twin. Nine pieces survive; three drop.The tool verifies deterministically; a dropped piece can never appear.
5. ReplyThe agent writes its answer from the verified list. Nine tiles and five purity chips render beside the text.The reply is written from verified output only.

Reading the reply #

The agent replied (verbatim, from the captured turn):

Opals are such a fun stone to shop, every piece shows its own play of color, so no two look quite alike.

These run deep in color, white and black opal, blues, purples, even fire opal, set mostly in gold over sterling silver with some solid gold and solid silver pieces too.

That play-of-color is the whole appeal, each stone flashes differently in the light, so pictures only tell part of the story.

Is there a color or a metal tone you're drawn to, or a budget I should work within?

Every sentence demonstrates a rule from the instructions: the opening line reacts to the stone rather than announcing a search; the second line carries what the tiles cannot (the breadth of the category, in plain words, with no counts); the third adds the expertise a search box lacks; the close is the only bold text on the screen and asks exactly one question that would most change the next search. No piece is named in prose, because the tiles carry the names and prices; no count is quoted; no jargon appears.

The chips, tap by tap #

The reply's chips read Sterling, 14K, 10K, 18K, 24K: the metal purity values present in this result, verbatim from the catalog, most results first, five to the row. No label heads the row, because the values are self-evident.

Tapping Sterling refined the search inside the same turn: the results were recomputed within the selection, the shelf re-rendered to the eight pieces that matched, and the next level's options came from the refinement's own counts. The conversation did not restart and the agent was not re-asked; the narrowing is navigation, not a new question. A back control returns to the previous level at any point.

The scenarios the prompts teach #

The system prompt ends with three worked scenarios. They teach order and reason; the agent never repeats one as a reply.

A piece the shopper named

"Is the sapphire pendant I saved still in stock?" The right move is refresh_products with that piece's exact object ID, answered from the record it returns. Searching again and presenting a similar piece as if it were the same one is the failure this scenario exists to prevent: the refresh tool accepts a record only when its own object ID matches the request.

Results that contradict the request

A search for a stone can return a perfume whose name contains it; a metal ask can return plated pieces whose titles contain the words. The taught move is to search again with the facet filter for what the shopper actually named, using the exact attribute and value from the tool's vocabulary, and curate the new result. Curating a contradicting piece into the display because the search returned it is the failure. If the catalog has no such value, the agent says what it could not match.

A rejected call

A call can be rejected for an invented facet value or an oversized query. The taught move is to correct it (the exact value the tool offered, or shorter terms) and carry on silently. Resending the same failing call, or telling the shopper about the retry, are both failures: the shopper sees only a working store.

Shapes for other asks #

The instructions carry four full worked examples that set the shape of the other conversation kinds:

  • A broad category gets one search, the tiles and chips as the first cut, one line on what the category runs deep in, and an invitation to narrow. Never a questionnaire, never an empty shelf, never a count.
  • A personal gift gets the human moment first (congratulate the milestone, acknowledge the reason), a first cut of classic gift pieces, and the one deciding question, with the tiles and the question arriving together.
  • A care question gets an answer in short plain paragraphs from the retrieved guide, a link to it, and a close that moves shopping forward. No advice the guide does not contain.
  • A service question gets the scan-friendly structure: warm opening, key rule with a short label, numbered steps with conditions, caveats, the help link, one honest line about what the agent cannot do, and a forward question.
