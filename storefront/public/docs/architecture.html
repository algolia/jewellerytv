How the Concierge works

Four things make one shopper exchange: the shopper, the JTV website, the Concierge agent, and the product catalogue. This page explains what each piece does, how an answer is produced, and the rules that keep every answer honest.

The pieces of the system #

Think of it as a small team:

  • The shopper visits the JTV website and describes what they want, in their own words. They never see anything except the page in front of them.
  • The JTV website is the shop itself: the pages shoppers browse and the chat window where they talk to the Concierge. It shows the products, checks every piece before it is displayed, and remembers what the shopper has saved or compared.
  • The Concierge is the AI agent hosted by Algolia. It holds the conversation: it understands what the shopper wants, decides when to ask a question and when to search, chooses what to show, and writes every word the shopper reads.
  • The catalogue is the live product data, stored in Algolia. It is the single source of truth for what JTV sells, at what price, in what stock. The Concierge and the website can read it; neither can change it.

How an exchange flows #

The same eight steps from the overview, with the detail a developer needs:

What each step really does:

  1. The shopper types a message such as "show me gold hoop earrings" into the chat.
  2. The website sends the message to the Concierge. The reply streams back as it is written, so the shopper sees words appear rather than waiting for a finished page.
  3. The Concierge decides what to do: ask a question, explain something, or search. Searching uses a product search that runs inside Algolia and looks only at prod_catalog, the product catalogue.
  4. When it has candidate pieces to show, the Concierge calls two helpers that live in the website: one fetches fresh details for specific pieces, and one arranges pieces into the titled groups shoppers see.
  5. Those helpers look up each piece in the catalogue through the website's server, using a key that can read but never write.
  6. Helpers return clean results: pieces that pass every check, and a plain reason for anything left out, such as out of stock. A piece the checks rejected can never appear on screen.
  7. The Concierge writes its reply from those results. A safety layer then reviews the finished text against JTV's rules; if it breaks one, the text is replaced before it stays on screen.
  8. The website shows the reply beside the approved product cards.

Rules that keep it honest #

Four rules decide how the pieces behave, and they are binding:

  • The Concierge does all the talking. Its instructions decide how it interprets, asks, searches and phrases. The website never writes shopper-facing speech and never fakes a Concierge reply, not even for error messages: transport problems show an honest system notice instead.
  • The website does all the checking. Anything deterministic, such as stock, price arithmetic, what may be displayed and what is saved, is validated in code. The Concierge cannot talk its way past a failed check.
  • The catalogue is read-only. Nothing in this system changes a product record, a search rule or any catalogue setting. Merchandising changes to the catalogue are made by the merchandising team through their own tools.
  • No scripts, no canned replies. The Concierge is taught by instructions and worked examples, never by hardcoded answers or keyword matching. That is why its behavior improves by editing its instructions, never by adding code.

Where the Concierge's settings live #

The Concierge is configured in Algolia's Agent Studio dashboard: its instructions, the description of its three tools (the tool sheet) and its safety rules. The website holds only connection settings, read by server/config.ts from the server environment. Their names, not their values:

SettingWhat it chooses
ALGOLIA_APP_IDWhich Algolia account holds the catalogue (required)
ALGOLIA_SEARCH_API_KEYThe read-only key the website uses to look up pieces (required)
JTV_CONCIERGE_DEVELOPMENT_AGENT_IDWhich Concierge configuration test runs talk to
JTV_CONCIERGE_PRODUCTION_AGENT_IDWhich Concierge configuration real shoppers talk to
The one mismatch to know about The website can only run the tools its build knows about, and the Concierge only knows the tools its configuration declares. If those two disagree, the website refuses the turn with a labelled tool_sheet_mismatch error and an honest system notice, rather than an agent that appears to fail; the same check reports on the health endpoint. Whenever something odd happens, first confirm which Concierge configuration the running website is pointed at.

The old system, now replaced #

Until October 22, 2026 the public website was served by the previous generation of the Concierge: more moving parts, three client-side helper tools, and an outdated product-filter list baked into its configuration. On that date the rebuilt system described on this page was promoted to production and the old configuration was retired. The website and the agent now both run the baseline: one Concierge definition, the native catalogue search tool, and the two helpers this website executes. The record of the swap is kept in Running and changing the system (soon).
